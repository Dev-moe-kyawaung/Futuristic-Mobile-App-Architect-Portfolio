Modularization Strategy

Multi-module architecture for scalability, team collaboration, and build optimization.

Module Structure

📱 :app

Application entry point, DI setup, minimal code

🎯 :feature:home

Home screen, navigation, business logic

👤 :feature:profile

User profile, settings, account management

⚙️ :feature:settings

App settings, preferences, configuration

🌐 :core:network

Retrofit, OkHttp, API clients, interceptors

💾 :core:database

Room, DAOs, entities, migrations

🎨 :core:ui

Shared components, themes, utilities

📊 :core:analytics

Analytics tracking, crash reporting

// settings.gradle.kts
include(
  ":app",
  ":feature:home",
  ":feature:profile",
  ":feature:settings",
  ":core:network",
  ":core:database",
  ":core:ui",
  ":core:analytics",
  ":core:common",
  ":testing"
)

// Dependency graph rules:
// - :app can depend on :feature:* and :core:*
// - :feature:* can depend on :core:* but NOT other :feature:*
// - :core:* should only depend on other :core:* modules
// - :testing is available to all modules for test dependencies
